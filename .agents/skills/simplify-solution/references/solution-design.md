# Simplify the proposed solution

Compare proposed entities, state, processing and dependencies with required scenarios and existing contracts. Before adding persisted fields or new protocols, inspect how existing data survives serialization and restoration and reaches UI actions. Derive values from existing data when it covers the required lifecycle, retaining structured storage when needed to preserve information. Reuse existing capabilities and remove duplicate sources of truth.

Choose the smallest solution that keeps failure handling, compatibility, security, accessibility and performance. Keep separation for a concrete responsibility or failure boundary. Record material choices and reasons in the current plan/design.
