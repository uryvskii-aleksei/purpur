# Пурпур

Сайт шоколадной фабрики «Пурпур» и основа виртуального ИТ-отдела: роли агентов, навыки, проверка решений и документация в одном репозитории.

## 1. Быстрый старт

Нужен Node.js 22 или новее. Установка зависимостей для текущей версии не требуется.

```sh
npm run dev
npm run department
npm test
npm run check
```

Сайт откроется по адресу [localhost:4173](http://localhost:4173). Остановить сервер можно сочетанием Ctrl+C. Опционально задайте переменную `PORT` для другого порта. Сервер слушает только `127.0.0.1`.

Доска отдела: [127.0.0.1:4174](http://127.0.0.1:4174/), команда `npm run department` в отдельном терминале. Показывает [задачи](tasks/README.md), ответственных, назначения, планы и результаты из файлов текущей рабочей копии. [Возможности и ограничения](tools/department/README.md).

## 2. Сайт

В [apps/site](apps/site/README.md) сохранена версия, подготовленная 26 октября 2026 года: пурпурный фирменный стиль, видео на первом экране, подарочные коллекции, каталог 221 товара, поиск, фильтры и корзина. У 29 товаров без подтверждённой фасовки заказ отключён. Каталог — снимок данных на 26 октября, автоматической синхронизации нет.

Демонстрация: [purpur-chocolate.abuzz-whale-0368.chatgpt.site](https://purpur-chocolate.abuzz-whale-0368.chatgpt.site/). Отправка заявок на сервер, онлайн-оплата и склад ещё не подключены. Пользователь скачивает заявку или отправляет её своей почтовой программой. Действующий магазин на purpur.spb.ru не изменён.

Исходники хранятся в `apps/site/public/`. Развёртывание не требует сборки. Перенос в GitHub сохраняет текущую демонстрационную площадку. Инструкции по публикации и ограничения — в [документации сайта](apps/site/README.md).

Для показа бизнесу опубликована [светлая витрина](https://purpur-chocolate.abuzz-whale-0368.chatgpt.site/concept/). Локальный просмотр: [localhost:4173/concept/](http://localhost:4173/concept/). Прежняя главная сохранена для сравнения. Решения, сценарии показа и границы концепции — в [документе концепции](docs/techprojects/site-concept/site-concept.md).

## 3. Виртуальный ИТ-отдел

Настроены 15 ролей и 18 навыков. Пользователь — CTO, основной координатор принимает запрос, выбирает нужных специалистов, объединяет доказательства и выполняет разрешённые внешние действия. Общие правила — в [AGENTS.md](AGENTS.md), полный состав и взаимодействие — в [документации отдела](docs/virtual-it-department.md).

| Область | Роли |
| --- | --- |
| Управление и требования | `coordinator`, `product-owner`, `business-analyst` |
| Пользовательский опыт и материалы | `designer`, `content-manager` |
| Архитектура и реализация | `architect`, `planner`, `coder`, `integration-engineer` |
| Качество и эксплуатация | `qa`, `reviewer`, `devops` |
| Продвижение, продажи и данные | `marketing` с режимами SEO/SMM, `sales`, `bi-analyst` |

Контракты лежат в `.agents/roles/`. Роли не создают постоянно работающих сотрудников или отдельную изоляцию. Модель и настройки рассуждения наследуются от пользователя, технические права и делегирование зависят от среды.

Профессиональные методы и критерии результата заданы в контрактах всех ролей. [Общий стандарт и проверка](docs/virtual-it-department.md#31-профессиональный-стандарт) дополняют их без изменения пользовательской модели и полномочий.

### 3.2. Рабочий процесс и CTO

Простая задача использует только нужные роли. Для комплексной задачи уточняются ценность и процесс, затем интерфейс, материалы и технические границы. Существенные открытые решения координатор собирает для CTO с вариантами, рекомендацией и последствиями. Уже принятые решения и разрешения действуют при передаче между специалистами.

QA проверяет пользовательские и бизнес-сценарии, reviewer — код и техпроекты. Самопроверка автора не считается независимой проверкой. Факты о продукции и коммерческие правила подтверждает соответствующий владелец бизнеса. PO готовит предложение приоритетов и бизнес-приёмки, но не одобряет себя от имени человека.

Исследование завершается техпроектом и передачей контекста. Реализация начинается по отдельному запросу. Задачи, их планы, назначения, проверки и следующий шаг хранятся в `tasks/<id>/README.md`. [Реестр задач](tasks/README.md) ведёт к этим записям. PR ссылается на план задачи, долговременные решения находятся в `docs/techprojects/`, полезные артефакты — рядом с задачей. Исполнители не меняют Git и внешние системы и не делегируют дальше. Подробности и примеры запросов: [работа отдела](docs/virtual-it-department.md), [разработка](docs/development.md).

### 3.3. Форматирование

Один хук `format-touched` обслуживает три среды и форматирует только затронутые существующие файлы внутри репозитория. Он пропускает настройки сред, не устанавливает зависимости и не блокирует работу, если локального Prettier нет. Сейчас Prettier не установлен. Конфигурации событий сохранены, фактическое включение зависит от поддержки хуков клиентом и его личных настроек. Тесты хука: `npm run test:harness`.

## 4. Интеграции

| Параметр | Текущее значение |
| --- | --- |
| Репозиторий | [uryvskii-aleksei/purpur](https://github.com/uryvskii-aleksei/purpur) |
| Базовая ветка и цель PR | `main` |
| Ветки задач | `feature/<id>-<slug>`, `bugfix/<id>-<slug>`. ID необязателен |
| Сайт | Статические HTML/CSS/JS, без сборки и сторонних JS-зависимостей |
| Проверки | Встроенный Node.js test runner, проверка синтаксиса, GitHub Actions |
| Задачи и артефакты | Файлы в этом репозитории. Внешний трекер не требуется |
| Figma | Не обязательна. Для задачи по макету нужны ссылка и доступная интеграция |
| MCP и секреты | В личных настройках среды или в секретах выбранного сервиса. Отключённый пример — `.codex/mcp-servers.example.toml`, [сравнение MCP](docs/techprojects/site-development/mcp-assessment.md) |

Учётные данные, личные настройки IDE и файлы заказов не коммитятся. GitHub — основное хранилище исходников. Публикация исходников не подключает оплату, CRM или доставку.
