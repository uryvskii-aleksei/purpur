# Пурпур

Сайт шоколадной фабрики «Пурпур» и основа виртуального ИТ-отдела: роли агентов, навыки, проверка решений и документация в одном репозитории.

## 1. Быстрый старт

Нужен Node.js 22 или новее. Установка зависимостей для текущей версии не требуется.

```sh
npm run dev
npm test
npm run check
```

Сайт откроется по адресу [localhost:4173](http://localhost:4173). Остановить сервер можно сочетанием Ctrl+C. Опционально задайте переменную `PORT` для другого порта. Сервер слушает только `127.0.0.1`.

## 2. Сайт

В [apps/site](apps/site/README.md) сохранена версия, подготовленная 26 октября 2026 года: пурпурный фирменный стиль, видео на первом экране, подарочные коллекции, каталог 221 товара, поиск, фильтры и корзина. У 29 товаров без подтверждённой фасовки заказ отключён. Каталог — снимок данных на 26 октября, автоматической синхронизации нет.

Демонстрация: [purpur-chocolate.abuzz-whale-0368.chatgpt.site](https://purpur-chocolate.abuzz-whale-0368.chatgpt.site/). Отправка заявок на сервер, онлайн-оплата и склад ещё не подключены. Пользователь скачивает заявку или отправляет её своей почтовой программой. Действующий магазин на purpur.spb.ru не изменён.

Исходники хранятся в `apps/site/public/`. Развёртывание не требует сборки. Перенос в GitHub сохраняет текущую демонстрационную площадку. Инструкции по публикации и ограничения — в [документации сайта](apps/site/README.md).

## 3. Виртуальный ИТ-отдел

Общие правила находятся в [AGENTS.md](AGENTS.md). Координатор в текущем чате уточняет задачу, выбирает навыки, принимает результаты и отвечает за итоговую проверку и разрешённые внешние действия.

| Роль | Ответственность |
| --- | --- |
| [planner](.agents/roles/planner.md) | Исследование, варианты решения, зависимости и план. Только чтение |
| [coder](.agents/roles/coder.md) | Реализация в назначенных файлах, регрессионные тесты и документация |
| [reviewer](.agents/roles/reviewer.md) | Независимая проверка кода или техпроекта. Только чтение |

Роли — инструкции для поддерживающей их среды. Они не создают постоянно работающих сотрудников или отдельную изоляцию. Делегирование зависит от возможностей среды и полномочий текущей задачи.

### 3.1. Навыки

| Навык | Когда применять |

| [figma-to-code](.agents/skills/figma-to-code/SKILL.md) | Реализация интерфейса по макету при доступной Figma-интеграции |

### 3.2. Рабочий процесс

Простую задачу можно реализовать непосредственно с проверками. Исследование заканчивается конкретным техпроектом для человека. После одобрения сохраняются декомпозиция и контекст для отдельного запуска реализации. Для GitHub план задачи живёт в описании PR, для локальной работы — в чате, долговременный техпроект — в `docs/techprojects/`. Подробности: [работа над проектом](docs/development.md).

### 3.3. Форматирование

Один хук `format-touched` обслуживает три среды и форматирует только затронутые существующие файлы внутри репозитория. Он пропускает настройки сред, не устанавливает зависимости и не блокирует работу, если локального Prettier нет. Сейчас Prettier не установлен. Конфигурации событий сохранены, фактическое включение зависит от поддержки хуков клиентом и его личных настроек. Тесты хука: `npm run test:harness`.

## 4. Интеграции

| Параметр | Текущее значение |
| --- | --- |
| Репозиторий | [uryvskii-aleksei/purpur](https://github.com/uryvskii-aleksei/purpur) |
| Базовая ветка и цель PR | `main` |
| Ветки задач | `feature/<id>-<slug>`, `bugfix/<id>-<slug>`. ID необязателен |
| Сайт | Статические HTML/CSS/JS, без сборки и сторонних JS-зависимостей |
| Проверки | Встроенный Node.js test runner, проверка синтаксиса, GitHub Actions |
| TFS | Не настроен. Сервер, проект, репозиторий, area, iteration и процесс должны быть выбраны явно |
| Figma | Не обязательна. Для задачи по макету нужны ссылка и доступная интеграция |
| MCP и секреты | В личных настройках среды или в секретах выбранного сервиса |

Учётные данные, личные настройки IDE и файлы заказов не коммитятся. GitHub — основное хранилище исходников. Публикация исходников не подключает оплату, CRM или доставку.
