# Схема каталогов Пурпура

## 1. Основание

28.10.2026 CTO попросил разложить проект так, чтобы первым шёл сайт, а позже появились корпоративные библиотеки, общие компоненты и мобильные приложения. Ориентир — ContentAI Frontend: приложения в `apps/`, общий код в `packages/`. Пустые каталоги не создаются.

## 2. Сейчас

| Каталог | Что там |
| --- | --- |
| `apps/site` | Новый сайт. Демонстрация и витрина. Старый магазин сюда не копируется |
| `docs/` | Бриф, техпроект и человеческая документация |
| `tasks/` | Бэклог. Одна задача — один каталог |
| `.agents/` | Роли и навыки отдела |

Каталога `packages/` нет. Общего кода для двух приложений ещё нет.

## 3. Когда что появляется

| Будущее | Куда | Когда |
| --- | --- | --- |
| Сайт | остаётся `apps/site` | уже есть |
| Общая библиотека или компонент | `packages/<имя>` | только когда его используют минимум два приложения |
| Мобильное приложение покупателя | `apps/mobile` | отдельный диалог и явный старт |
| Корпоративные библиотеки | `packages/` | после того как появится второе приложение |

Имя каталога — lowercase kebab-case. Секреты, персональные данные и исходники старого сайта без отдельной передачи сюда не кладутся.

## 4. Чего не делаем этим шагом

Не создаём пустые `packages/` и `apps/mobile`. Не переносим действующий магазин. Не меняем DNS.
