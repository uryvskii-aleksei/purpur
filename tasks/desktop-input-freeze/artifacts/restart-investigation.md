# Проверка после перезагрузки Mac

## 1. Источник и подтверждённый механизм

28 октября 2026 года, 12:10–12:22 МСК. Рабочая папка Purpur, ветка `feature/site-business-concept`, HEAD `5e6c0b9b800b19a9fe5025728a4d9b47c4409890` с незакоммиченными правками. Версия приложения 26.1023.50603. По системному времени Mac загрузился в 12:02:03 МСК. CTO подтвердил, что физические клики восстановились.

| Наблюдение | До перезагрузки | После перезагрузки |
| --- | --- | --- |
| Левая кнопка, combined-session | Нажата, три последовательные пробы | Отпущена |
| Левая кнопка, HID-state | Нажата, три последовательные пробы | Отпущена |
| Клики по словам CTO | Не работают во всех приложениях | Работают |
| Движение указателя и CmdTab | Работают | Пользователь не сообщил о нарушениях |

Подтверждено залипшее состояние кнопки на уровне macOS. Это не позволяет определить, какой процесс или устройство его создало. Остановка Computer Use во время сбоя не сбросила состояние. Перезагрузка его сбросила. Текущие три пробы в 12:21 МСК показывают все кнопки отпущенными в обоих источниках. Проверка не отправляла событий ввода.

## 2. Проверенные гипотезы

- Служба Computer Use автоматически запустилась вместе с приложением после перезагрузки, PID1412. При ней клики работали, а кнопки были отпущены. Одно наличие службы не объясняет отказ.
- Ограниченный запрос системного журнала службы за 10:00–11:50 МСК нашёл сетевые ошибки и ошибку опроса разрешений в 11:44. Событий, доказывающих потерянный mouse-up, не найдено. Отсутствие записи не исключает такую ошибку.
- В журнале приложения есть `Pet drag started` в 10:28:22 МСК с `nativeHandoffRequested=true`. Нет последующей записи успешной передачи в нативный обработчик. Статическое чтение кода установленного приложения показало, что начало обычного нажатия тоже может создать эту запись. Поэтому отсутствие записи завершения само по себе не доказывает зависшее перетаскивание. CTO не помнит или не подтверждает перетаскивание.
- После перезагрузки прочитано 10 event-tap вместо 26 до неё. Активные фильтры Siri относятся к клавиатуре. Logitech в текущем снимке слушает перемещение мыши пассивно. Их число и задержки не доказывают источник залипания кнопки. Процессы не изменялись.
- Параметры DragLock/Dragging встроенного трекпада выключены. Доступны встроенный трекпад и Bluetooth-мышь. Переключение устройств во время сбоя не проверялось.
- Активные процессы прежнего внешнего трекера ранее не обнаружены. Доказательств связи остатков переноса с отказом кликов нет. Личные настройки других проектов не менялись.

## 3. Применённые меры

- По прямому запросу CTO анимированный персонаж выключен через штатный инструмент Pets. Ответ подтвердил `active_pet_id=default`. Персонаж и его данные не удалялись.
- Отправлен SIGTERM только автоматически запущенной службе SkyComputerUseService PID1412. Проверка в 12:21 МСК подтвердила, что служба не запущена. Основное приложение и системные службы не завершались.
- В `AGENTS.md` и процедуре operations закреплена изоляция нативной автоматизации на этом Mac. Следующие диалоги должны читать это ограничение. Это правило поведения агентов, а не изменение системных разрешений или отключение автозапуска службы в приложении.
- Добавлена ручная команда `npm run diagnose:input`. Она читает три снимка состояния кнопок и наличие службы. Обращения ограничены по времени. Команда не отправляет клики, не открывает окна, не меняет права и не работает в фоне. Недоступное чтение не выдаётся за исправный ввод.

Причина не установлена окончательно. Изоляция уменьшает доступ к подозреваемому пути, но не доказывает исправление дефекта приложения или драйвера. Исполняемые файлы ChatGPT не изменялись. Опасное воспроизведение на рабочем Mac не выполнялось.

## 4. Проверка и продолжение

Реальная пассивная проба после отключений: три раза все кнопки false/false, служба отсутствует. В песочнице та же команда завершилась по пятисекундному ограничению с кодом1 и unavailable. Это проверка ограниченного отказа, а не повторный отказ мыши. Автоматические проверки: npm test — 63/63, npm run check и git diff --check — успешно. Пять новых тестов покрывают краткое нажатие, устойчивое состояние, тайм-аут, неполный ответ и неподдерживаемую ОС. quick_validate.py не запущен успешно из-за отсутствия PyYAML. YAML frontmatter навыка operations проверен Ruby/Psych. Независимая проверка не проводилась. Обычные пользовательские клики подтверждены после перезагрузки, отдельного подтверждения после мер пока нет.

Если симптом повторится, сначала снять ограниченную диагностику из активного диалога. При движущемся курсоре и работающем переключении приложений можно изолировать физическую Bluetooth-мышь её выключателем и проверить встроенный трекпад. Это ещё не выполнялось и не является доказанным исправлением. Не просить перетаскивать элементы в настройки при отказавших кликах. Не запускать нативную автоматизацию для восстановления ввода.
