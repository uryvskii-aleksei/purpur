# Ограниченная диагностика зависаний Mac

## 1. Наблюдения

28.10.2026 CTO подтвердил: не реагировал весь Mac. Точное время двух эпизодов неизвестно. macOS, MacBookPro18,1,16GiB,10CPU. При проверке серверы4173/4174 имеют CPU0%, память около56/38MiB. Системный memory_pressure -Q вернул free64%. Это текущий снимок, он не исключает прошлый пик.

Найден JetsamEvent от07:00+0300. Крупнейший процесс в снимке — Codex(Service), но единственная явная причина завершения per-process-limit относится к другому системному процессу. Это не доказательство причины потери ввода. Отчёты Codex за предыдущий вечер относятся к disk writes. В коротком журнале есть очистка буферов клиентов WindowServer около09:58:52, причём connectionIsUnresponsive:0. Привязка к двум эпизодам не установлена. WindowServer — компонент macOS.

## 2. Следы переноса и фактический запуск

В проектных MCP-файлах активных подключений другого проекта нет. codex mcp list показывает node_repl/cua_repl, отключённые примеры и системные инструменты. В личном глобальном ~/.cursor/mcp.json остаётся включённая запись прежнего внешнего трекера с организацией и default-project другой работы. Значения учётных данных не копировались в репозиторий. В текущем Codex эта запись не загружена, процессов её runner при проверке нет. Глобальные настройки других проектов не менялись.

В проекте сохранены3старых локальных hook-файла,75файлов сторонних навыков и9служебных файлов старого визуального помощника. Действующие проектные hook-конфиги вызывают только format-touched. Старый Windows-совместимый wrapper в них не указан. Сервер старого помощника не запущен, его порт не слушается. Наличие этих файлов само по себе не объясняет зависание Mac. Служебный кэш .superpowers/ добавлен в .gitignore, исходные файлы сохранены.

## 3. Сделано и ограничения

Устаревшее соединение браузерных инструментов сброшено. После этого чтение страницы и управление её DOM восстановились. Общесистемное исправление этим не доказано. Проверки выполняются последовательно без новых параллельных агентов и нативных кликов/клавиш. Декоративный ролик приостанавливается вне видимости и в скрытой вкладке. Это ограничение ненужной работы, не установленная причина инцидента.

Широкий запрос системных журналов остановлен по12-секундному лимиту. Успешно выполнен более короткий запрос. Сырые журналы, адреса с ключами, конфигурации с токенами и дампы в Git не сохранялись. Причина двух зависаний пока не установлена. Следующий шаг — сопоставить время или воспроизведение со свежими системными событиями. Стресс-тест, перезапуск приложения/WindowServer, изменение системных прав и удаление чужих настроек не выполнялись.

## 4. Активный эпизод и продолжение после перезапуска

28.10.2026 около11:29–11:40МСК пользователь подтвердил: курсор движется, CmdTab переключает приложения, клики не действуют повсюду, ввод в чате остаётся возможным. Остановка SkyComputerUseService PID6728 не восстановила клики. Чтение публичного CGEventSourceButtonState подтвердило левую кнопку зажатой в combined-session и HID-state, в том числе в3последовательных пробах. Это подтверждённый симптом. Кто оставил это состояние и что его удерживает, не установлено.

Получен список26event-tap. У некоторых клавиатурных фильтров отражены большие задержки. Это само по себе не доказывает причину отказа кликов, процессы этих фильтров не изменялись. Отправка событий через CoreGraphics не выполнялась.

Попытка штатного безопасного клика не завершилась. CUA запретила управление приложением Codex. Получение Finder зависло в инструменте и сбросило его сессию. Пользователь сообщил, что появившаяся настройка требует перетаскивания мышью, что невозможно при этом инциденте. Новые разрешения не выдавались. Повторно запущенный SkyComputerUseService PID30680 остановлен. После остановки состояние левой кнопки по-прежнему True/True. Главные приложения и WindowServer не завершались.

Пользователь предложил перезагрузить Mac. Перед перезагрузкой сохраняется эта передача. После возвращения: сначала подтвердить обычные физические клики без вызовов CUA и новых разрешений. Затем только терминальными read-only проверками проверить состояние кнопок и процессы. Не запускать нативную автоматизацию для проверки сайта до выяснения причины. Сравнить чистое состояние после старта с предшествующим залипшим состоянием. Локальные серверы4173/4174 после перезагрузки могут требовать обычного повторного запуска.

Правка растушёвки белой карточки сохранена в concept-video.css: убрана рамка, добавлена светлая мягкая тень. Текст не фильтруется. npm run check и diff --check прошли, визуальная проверка этой небольшой правки не проводилась во время инцидента.
