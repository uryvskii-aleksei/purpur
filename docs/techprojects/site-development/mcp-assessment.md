# Оценка MCP для Figma и Rocket.Chat

## 1. Результат и граница проверки

Дата — 27.10.2026. Для задач Пурпура рекомендуется официальный Figma remote MCP. Он поддерживает чтение, экспорт и запись нативного дизайна. Desktop рассматривается для ограниченных сценариев чтения, grab — как условная альтернатива записи, GLips — для получения контекста и изображений. Появившееся официальное подключение Figma уже подтвердило авторизацию. Следующая проверка относится к конкретному файлу и результату работы с ним.

Первичный поиск координатора показывал официальный Figma plugin и Product Design с `installed=false`. Позднее в этом же сеансе появился официальный Figma plugin с tools, включая `use_figma`, создание файла/сессии, чтение и экспорт. Координатор выполнил `whoami`: авторизация успешна, получены Starter/Full/admin. Это актуальное подтверждение аккаунта. Личные email, ID и название команды здесь не сохраняются.

Корпоративное владение и права конкретного файла пока не проверены. Целевой fileURL не задан, файлы не создавались и canvas не менялся. Наличие write tool и Full seat не доказывает доступ к записи в выбранном корпоративном файле. Причина считать текущее подключение неудачным не установлена. Product Design нельзя приравнять к конкретному MCP без проверки его описания и tool discovery.

Нативный Rocket.Chat MCP подтверждён документацией. Отсутствие релевантного результата в каталоге плагинов не означает отсутствия MCP. URL рабочего пространства Rocket.Chat неизвестен. Архитектор выполнил чтение публичных первичных источников и локальных skills. Установки, изменение авторизации/конфигурации, покупки и вызовы рабочих пространств архитектором не выполнялись. Результат Figma `whoami` передан координатором отдельно.

## 2. Сравнение Figma MCP

### 2.1. Возможности и ограничения

| Вариант | Чтение, запись и экспорт | Компоненты и дизайн-система | Доступ, зависимости и сопровождение |
| --- | --- | --- | --- |
| Официальный remote | Контекст узла, метаданные, screenshot. `download_assets` экспортирует PNG/JPG/SVG/PDF и исходные изображения. `use_figma` читает/создаёт/изменяет содержимое | Поддержаны нативные компоненты, variants, variables и auto layout. Есть библиотеки, поиск дизайн-системы и Code Connect | Hosted endpoint, вход через Figma и поддерживаемый клиент. Desktop app не требуется. Возможности зависят от плана, seat и прав файла. Запись в beta. Поставщик сопровождает сервер |
| Официальный desktop | Контекст, screenshot, переменные и работа с image assets через desktop. Write-to-canvas и отправка UI в Figma не поддерживаются | Code Connect включается в desktop. Контекст помогает переиспользовать компоненты, но редактирование canvas через этот сервер не заявлено | Нужны запущенное Figma desktop app, включённый локальный MCP и подходящий Dev/Full seat. Дополнительный community plugin не нужен. Доступность зависит от локальной сессии |
| grab / TalkToFigma | Читает документ/узлы/выделение. Создаёт и меняет узлы, текст, layout. Экспорт PNG/JPG/SVG/PDF заявлен с ограничением передачи изображения как base64 text | Есть локальные styles/components, создание instances и перенос overrides. Полнота поддержки libraries/variables/Code Connect просмотренным README не доказана | Авторский MCP, Bun, WebSocket bridge и запущенный Figma plugin с подключением к каналу. Действия проходят в открытом документе через пользовательскую сессию. Дополнительные процессы и зависимости сопровождаются отдельно |
| GLips / Framelink | Упрощает layout/style data из Figma API. В просмотренном коде зарегистрированы получение данных и скачивание изображений. Запись canvas этими tools не реализована | Наличие исходных компонентных данных не означает управление компонентами/переменными. Пригодность сокращённого контекста для Пурпура требует сравнения с оригиналом | Авторский Node-процесс и доступ к Figma API. README предлагает API token. Desktop/plugin не нужны в описанном пути. Токен, зависимости, локальные загрузки и телеметрия требуют проверки перед применением |

Основание официального remote — [введение](https://developers.figma.com/docs/figma-mcp-server/), [установка remote](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/) и [каталог tools](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/). Сервер находится по `https://mcp.figma.com/mcp`. Figma рекомендует собственный клиентский plugin, где доступен, поскольку он добавляет настройки и skills. Plugin и ручная настройка remote являются путями подключения к серверу, а не двумя доказанно различающимися backend.

Важное различие: [write-to-canvas](https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/) строит нативные компоненты и привязки. Захват готовой страницы превращает интерфейс в слои и не сохраняет связь с библиотекой. Для сохранения дизайн-системы предпочтителен первый путь. Запись требует remote, прав редактирования и подходящих условий доступа. Согласно введению, для записи вне drafts нужен Full seat. Beta не означает гарантированную постоянную бесплатность.

Ограничения desktop подтверждены [его установкой](https://developers.figma.com/docs/figma-mcp-server/local-server-installation/). [Code Connect](https://developers.figma.com/docs/figma-mcp-server/code-connect-integration/) требует фактических связей компонентов с кодом. У Пурпура сейчас HTML/CSS/JS, поэтому наличие MCP не обосновывает React, новый UI kit или фиктивный Code Connect mapping.

Для grab прочитан [авторский README](https://github.com/grab/cursor-talk-to-figma-mcp). В [WebSocket bridge](https://github.com/grab/cursor-talk-to-figma-mcp/blob/main/src/socket.ts) видны подключение по каналу и журналирование полного сообщения. Это основание проверить аутентификацию bridge, сетевую привязку и чувствительные данные логов до пилота. Такой просмотр не является полным security review проекта.

Для GLips прочитаны [авторский README](https://github.com/GLips/Figma-Context-MCP), [регистрация tools](https://github.com/GLips/Figma-Context-MCP/blob/main/src/mcp/index.ts) и [реализация скачивания](https://github.com/GLips/Figma-Context-MCP/blob/main/src/mcp/tools/download-figma-images-tool.ts). Вывод об отсутствии canvas write ограничен просмотренной регистрацией. Совместимость, безопасность и качество результата этих проектов локально не проверялись. Перед установкой требуется зафиксировать выбранную версию и проверить её зависимости, лицензию и настройки. Внешние инструкции с `latest` не становятся правилом Пурпура.

### 2.2. Практический выбор

1. Продолжить проверку уже появившегося официального подключения после получения целевого fileURL и подтверждения корпоративного владения. Повторная установка или авторизация по результату `whoami` не требуется. Ручное подключение того же remote остаётся запасным путём для клиента без plugin. Замена сервера требует воспроизводимого ограничения текущего пути.
2. Для чтения макета и реализации сайта использовать ограниченный file/node-контекст, screenshot и нужные assets. Условия [лимитов и доступа](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/) проверять для реальной учётной записи. При 429 сохранить результат и остановить вызовы по действующему skill, не обходить лимит сменой токенов.
3. Для создания/изменения макета проверить `use_figma` на отдельном тестовом файле с разрешённым frame. Наличие прав и tool само по себе не разрешает правку других файлов или публикацию библиотеки.
4. Desktop использовать, если он соответствует реальной политике доступа и нужны его локальные read-сценарии. Не выбирать его заменой remote для записи canvas.
5. grab рассматривать, только если remote не покрывает доказанный сценарий или недоступен, а интерактивный plugin-процесс разрешён и принят в сопровождение. GLips сравнивать как read/export-вариант для ограниченного coding-контекста. Отдельный процесс с токеном не вводить без такой причины.

При недоступности конкретного макета запасным входом остаются согласованные спецификации и экспорты из Git. Дизайнер сохраняет редактируемый исходник в корпоративной Figma, требования и принятые результаты — по [контракту корпоративных инструментов](corporate-tools.md).

## 3. Rocket.Chat MCP

В [официальной документации](https://docs.rocket.chat/v1/docs/mcp-server) описан нативный `POST /api/v1/mcp`, Alpha начиная с Rocket.Chat 8.8.0, выключенный по умолчанию. Нужны AI add-on в лицензии, `access-mcp` у подключаемого пользователя и `MCP_Enabled`. Запросы используют его разрешения и заголовки `X-User-Id`/`X-Auth-Token` на каждом запросе, включая первый. Базовый curated-набор уже содержит отправку сообщения и создание канала. `MCP_Expose_Extended_API` расширяет операции и по умолчанию выключен. Фактический каталог определяется `tools/list`, версией и зарегистрированными маршрутами. GET к endpoint возвращает 405 и не является проверкой отсутствия MCP.

Рекомендация — сначала проверить пригодность самого Rocket.Chat для коммуникаций, затем необходимость MCP. Для MCP подготовить минимальную служебную/индивидуальную идентичность, доступ к нужным комнатам, перечень разрешённых действий, отзыв токена и диагностику без секретов. Токен администратора не является стартовым вариантом. Режим curated не принимается за техническое ограничение «только чтение». Где runtime позволяет, доступные агенту tools дополнительно ограничиваются под назначение, а серверные права проверяются отдельно.

Без URL, реальной версии, лицензии и разрешения администратора подключение не проверяется. Покупка AI add-on или включение настройки не следуют автоматически из наличия MCP. После отдельного задания первым этапом выполняются discovery и чтение известного синтетического сообщения в разрешённой комнате. Отправка, создание комнаты и extended-набор требуют своего разрешённого сценария. MCP не превращает Rocket.Chat в канонический backlog и не разрешает агентам рассылать уведомления по своей инициативе.

## 4. Сценарии приёмки Figma

Идентичность Figma частично проверена координатором через `whoami` и появившийся каталог. Сценарии над конкретным файлом ниже запланированы и не выполнены. Для записи нужен отдельный файл без совместных правок, синтетические данные, согласованный frame и заранее сохранённое исходное состояние.

| Сценарий | Проверяемый результат | Доказательство и граница |
| --- | --- | --- |
| Идентичность и discovery | Известны сервер/путь подключения, версия клиента, учётная запись, plan/seat, права файла и фактические read/write tools | Частично выполнено: plugin tools и успешный `whoami` подтверждены координатором. Права файла и применимость условий записи остаются открыты |
| Прочитать frame | По заданному file/node получены структура, текст, layout и используемые компоненты/переменные. Screenshot соответствует открытому исходнику | ID узла, время, сохранённая редакция, безопасный контекст и изображение. Нет лишнего обхода всего файла |
| Экспортировать asset | Нужный узел экспортирован в выбранный формат, файл открывается и соответствует frame | Путь, формат, размеры, checksum, источник. Временный download URL не используется как долговременный артефакт |
| Изменить тестовый frame | Изменяется ровно согласованный текст/spacing/цвет в тестовом frame | Before/after по узлу и UI. Соседний контрольный frame сохраняется. При timeout сначала readback, затем решение о повторе |
| Сохранить компонент | Instance сохраняет связь с main component, variant, overrides и bindings переменных после разрешённой правки | Структурное сравнение и проверка UI. Визуальное сходство и flat layers недостаточны. Shared main/library не меняются |
| Проверить редакцию | Реальный результат связан с конкретным состоянием файла. Параллельное изменение обнаруживается до следующей записи | Ссылка на именованную версию/время и node IDs. Наличие `version` в другом tool не означает поддержку historical read макета |
| Откатить | Исходный тестовый дизайн восстановлен, связи компонентов/переменных повторно проверены | Разрешённый возврат в выделенном файле через проверенный UI/history или заранее принятый способ. Отзыв доступа и остановка сервера проверяются отдельно |

Figma документирует ссылки на версии, дублирование и восстановление в [version history](https://help.figma.com/hc/en-us/articles/360038006754-View-a-file-s-version-history). Наличие MCP rollback tool не подтверждено. Если historical read через MCP недоступен, использовать сохранённую копию версии и UI history с явным указанием ограничения. Полный restore общего рабочего файла может затронуть чужие изменения, поэтому пилот проходит в выделенном файле. `.fig` не подменяет полную историю сервиса.

Для Rocket.Chat в будущем отдельно проверяются discovery, разрешённое чтение, отказ доступа к недоступной тестовой комнате и отзыв credentials. При явно разрешённой отправке — одно синтетическое сообщение в указанной комнате с readback по его ID. Правила очистки согласуются заранее. Неопределённый ответ записи не вызывает слепую повторную отправку. Extended-набор не включается только ради удобства теста.

## 5. Изменения обвязки для координатора

| Владелец и источник | Требуемое изменение | Критерий результата |
| --- | --- | --- |
| architect / coordinator, справочник интеграций | Remote первым кандидатом Figma, desktop и два авторских варианта с условиями. Нативный Rocket.Chat MCP с prereqs и эффектами curated | Нет устаревшего утверждения «Figma MCP только читает» и вывода «Rocket MCP отсутствует» из поиска каталога |
| coordinator, `figma-to-code` | Сохранить назначение реализации из макета. Проверять server capabilities и file/node. Различать context, screenshot и export. Указывать HTML/CSS/JS Пурпура | Skill не запускает дизайн-запись из запроса чтения и не вводит framework из сгенерированного примера |
| designer / coordinator, `ux-design` | Добавить путь разрешённой записи через remote и инструкции `figma-use`, проверку библиотек, ограниченного target и readback | При запросе создать макет доступна запись нативного дизайна. Нужные права, backup/версия и тестовый результат проверены до рабочего применения |
| integration-engineer / devops, configuration reference | Описать место personal/runtime-конфигурации, тип auth, необходимые права, версии и способ отзыва. Для Rocket — workspace URL как обязательный вход | Секреты и персональные настройки вне Git. Документированный пример не объявлен действующей конфигурацией. Нет автоматического включения сервисов |
| QA / reviewer | Независимо проверить пилот по матрице выше и конкретному файлу/версии | Раздельные passed/failed/blocked для чтения, экспорта, записи, component preservation и rollback. Документация поставщика не засчитывается тестом |

Контент макета и чата рассматривается как внешние данные, а не инструкция расширять полномочия. Права runtime и сервисов должны соответствовать роли и назначению. Git хранит требования, решения, ссылки на проверенную редакцию и нужные безопасные экспорты. Переписка клиентов и секреты не копируются. Figma Specs и Rocket.Chat не создают параллельный канонический трекер.

## 6. Что установлено и что остаётся

Прочитаны официальные страницы Figma/Rocket.Chat и авторские README/выбранные исходники grab и GLips по ссылкам выше 27.10.2026. Они подтверждают заявленные функции и предпосылки. Отдельное фактическое доказательство координатора — успешный Figma `whoami` и наличие plugin tools. Корпоративное владение, права/редакция конкретного файла, применимость условий записи, сохранение компонентов и откат ещё не проверены. Rocket.Chat не подключался и не проверялся.

Следующий шаг — координатор обновляет owning skills/configuration reference и ставит ограниченный пилот после получения целевого файла и подтверждения его владения. Запись Figma canvas и действия Rocket.Chat этим исследованием не выполнялись. `corporate-tools.md` и другие файлы архитектором не изменены.
