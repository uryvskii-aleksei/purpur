# Продолжение работы на другом ПК

## 1. Что переносится

Исходники сайта, каталог и медиаматериалы, бизнес-бриф, роли, навыки, адаптеры и проверки находятся в Git. Личные инструкции и настройки Codex находятся вне репозитория. Их подготовленный архив переносится отдельно и не публикуется в GitHub.

Синхронизация чатов и доступ к локальной папке — разные вещи. Вход в тот же аккаунт не заменяет клонирование исходников и настройку нового рабочего каталога. См. [официальную документацию о проектах](https://learn.chatgpt.com/docs/projects).

## 2. Получение проекта

Нужны Git, Node.js 22 или новее и Codex. Для сайта установка npm-зависимостей не требуется. Команды ниже выполняются в PowerShell. Папку для клонирования можно выбрать любую свободную.

```powershell
git clone https://github.com/uryvskii-aleksei/purpur.git Purpur
Set-Location Purpur
git fetch origin
git switch --track origin/feature/site-business-concept
```

На 27.10.2026 PR #1 и #2 слиты в `main`. Новый концепт находится в [PR #3](https://github.com/uryvskii-aleksei/purpur/pull/3), ветка `feature/site-business-concept`, проверенный коммит `5e6c0b9b800b19a9fe5025728a4d9b47c4409890`. Если PR позже слит или ветка изменилась, сначала проверить актуальное состояние GitHub. Не откатывать чужие изменения к указанному снимку.

Вместо скачивания из GitHub можно клонировать приложенный `Purpur.bundle`. Он сохраняет локальную историю и ветки на момент упаковки. Пример из папки распакованного комплекта:

```powershell
git clone --branch feature/site-business-concept .\Purpur.bundle .\Purpur
Set-Location Purpur
git remote set-url origin https://github.com/uryvskii-aleksei/purpur.git
git fetch origin
```

Из bundle можно работать без сети. В этом случае отложить `git fetch`, а перед последующими отправками сначала сверить состояние GitHub.

## 3. Личные настройки Codex

На новом ПК войти в Codex, добавить локальную папку `Purpur` как основной рабочий каталог проекта и открыть её в доверенном режиме, если пользователь доверяет исходникам. [Личные и проектные конфигурации](https://learn.chatgpt.com/docs/config-file/config-basic) применяются с учётом требований клиента и организации. В репозитории нет личного `.codex/config.toml`.

В отдельном комплекте находятся:

| Файл или каталог | Как использовать |
| --- | --- |
| `codex/AGENTS.md` | Восстановить личные правила в пользовательском каталоге Codex, обычно `%USERPROFILE%\.codex`. При существующем файле сначала сравнить и объединить |
| `codex/config.preferences.toml` | Перенести выбранные настройки в пользовательский `config.toml`, сохранив остальные настройки нового ПК |
| `codex/skills/` | Перенести два личных навыка в пользовательский каталог навыков. При совпадении имён сначала сравнить содержимое |
| `reference/desktop-preferences.json` | Восстановить желаемые настройки интерфейса через приложение |
| `reference/integrations.json` | Справочник локальных MCP-конфигураций. Исполняемые пути требуют адаптации, секреты задаются заново. Файл не подключает серверы автоматически |
| `reference/plugins.json` | Список настроенных плагинов и найденных кэшей. Кэш не доказывает, что плагин включён или авторизован. Нужные плагины проверить в приложении |
| `reference/git-preferences.json` | Сверить имя и почту автора Git и настройки текста. Пароли и credential helper не переносятся |
| `CONTINUE.md` | Контекст проекта и текст первого запроса на новом ПК |

Если на новом ПК задан `CODEX_HOME`, использовать его вместо стандартного пути. Не заменять весь существующий профиль. Личные [инструкции AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) применяются наряду с инструкциями репозитория.

В архив намеренно не включены `auth.json`, токены, браузерные профили и cookies, базы чатов, системные навыки, кэши плагинов и платформенные исполняемые файлы. Личная история чатов не импортируется этим комплектом. Для продолжения достаточно `CONTINUE.md` и исходников, даже если прежний чат недоступен.

Локальные разрешения, доверие к хукам, подключения сервисов, Windows sandbox и пути к инструментам проверяются заново на целевом ПК. Их нельзя восстановить одним копированием старых абсолютных путей. Node REPL, Browser и Computer Use следует настроить штатными средствами установленного клиента. TFS и другие интеграции иных проектов не являются зависимостями «Пурпура».

## 4. Проверка готовности

Из корня клонированного проекта:

```powershell
node --version
git status --short
npm run check
npm test
npm run dev
```

Открыть [localhost:4173/concept/](http://localhost:4173/concept/). Старый локальный адрес на другом ПК сам по себе не продолжает работать, сервер нужно запустить заново. Для остановки использовать Ctrl+C. Наличие адаптера роли не гарантирует поддержку функции установленной версией Codex. Проверить, что клиент видит инструкции проекта, 15 ролей и 19 навыков. Проверка `npm run check` подтверждает файлы обвязки, но не авторизацию внешних сервисов.

Работу можно продолжать, когда выбран актуальный исходник концепта, проверки прошли и Codex видит нужную папку и инструкции. Для локальной работы над сайтом не нужны оплата, CRM, TFS или повторная публикация демонстрации.

## 5. Точка продолжения

Бизнес хочет больше розничных заказов подарков, меньше ручной обработки, а также оптовые и корпоративные обращения. Текущие каналы — телефон, почта и мессенджеры. Единого места регистрации пока нет. Первый рабочий выпуск должен принимать и регистрировать заявку с подтверждением менеджером. Полный онлайн-заказ — после утверждения концепции.

[Опубликованная светлая концепция](https://purpur-chocolate.abuzz-whale-0368.chatgpt.site/concept/) и [предыдущий вариант](https://purpur-chocolate.abuzz-whale-0368.chatgpt.site/) доступны для сравнения. Демонстрация только подготавливает текст заявки, не подтверждает её получение, оплату или резервирование. Действующий магазин фабрики не менялся.

Далее прочитать `AGENTS.md`, `docs/site-brief.md`, `docs/virtual-it-department.md`, документ концепции `docs/techprojects/site-concept/site-concept.md` в ветке PR #3 и его актуальное описание. Концепт прошёл независимые QA и ревью. В последней проверке — 41 успешный тест, один тест симлинков пропущен на Windows. CI PR #3 был успешным. Изменения окружения на новом ПК требуют собственной проверки.

Следующее предметное решение — получить оценку бизнеса по визуальному направлению и сценариям. Слияние PR #3, утверждение бизнесом и подключение рабочего приёма заявок ещё не разрешены. При возобновлении сначала сверить актуальное состояние PR. Перенос проекта сам по себе не запускает новые доработки или публикацию.
